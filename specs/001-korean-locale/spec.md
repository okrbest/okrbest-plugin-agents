# Feature Specification: 한국어 로케일 지원

**Feature Branch**: `001-korean-locale`

**Created**: 2026-11-09

**Status**: Draft

**Input**: User description: "한국어 로케일 지원 (ko). 플러그인 webapp과 server의 사용자 표시 문자열을 한국어로 제공한다. webapp은 `webapp/src/i18n/ko.json`을 추가하면 `index.tsx`의 `registerTranslations`·`getStaticIntl`이 사용자 로케일 `ko`로 자동 로드한다 (en.json 1,029개 키 전부 번역, ICU plural/select/tag 구조 유지, 한국어는 CLDR 복수 범주가 other뿐이므로 plural은 other만). server는 `i18n/ko.json`(en.json 12개 id)을 추가하고 `i18n/i18n.go` Init()에 로드 줄을 넣는다. `temp/korean` 브랜치의 기존 번역 79개(webapp)·12개(server)를 참고해 용어를 일관되게 쓴다(에이전트, 요약, 도구 등). 번역 품질 검증: webapp `translations.test.ts`를 ko.json도 검사하도록 확장(ICU 파싱, en.json 키 집합과 일치, 자리표시자 `{name}` 집합 일치), server는 로더가 ko 로케일에서 번역을 돌려주는 테스트. 리브랜드 문자열은 다루지 않는다(Mattermost/Agents 제품명은 원문 유지)."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 한국어 사용자가 플러그인 화면을 한국어로 본다 (Priority: P1)

Mattermost 계정 언어를 한국어로 설정한 사용자가 Agents 플러그인의 모든 화면(오른쪽
패널의 채팅, 에이전트 선택기, 시스템 콘솔 설정, 채널 메뉴, 도구 승인 카드, 요약·회의
기능 안내)을 열었을 때, 영어가 섞이지 않은 한국어 문구를 본다. 언어를 영어로 되돌리면
기존 영어 문구가 그대로 나온다.

**Why this priority**: 이 포크의 1급 로케일은 한국어다(constitution 원칙 V). 사용자가
직접 마주치는 문구가 거의 전부 웹 화면에 있으므로, 이 이야기 하나만 끝나도 체감 가치가
가장 크다.

**Independent Test**: 계정 언어를 한국어로 바꾼 뒤 플러그인 화면을 훑어 영어 문구가
남아 있는지 확인하면 된다. 서버 쪽 작업 없이도 검증·배포할 수 있다.

**Acceptance Scenarios**:

1. **Given** 계정 언어가 한국어인 사용자, **When** 오른쪽 패널에서 에이전트 채팅을 열면,
   **Then** 입력창 안내·버튼·빈 화면 안내가 모두 한국어로 보인다.
2. **Given** 계정 언어가 한국어인 시스템 관리자, **When** 시스템 콘솔의 Agents 설정
   페이지를 열면, **Then** 설정 항목 이름·도움말·경고 문구가 한국어로 보인다.
3. **Given** 계정 언어가 한국어인 사용자, **When** 도구 승인 카드에 "검토되지 않은 도구"
   개수가 표시되면, **Then** 개수가 1이든 여럿이든 자연스러운 한국어 문장으로 보인다
   (한국어는 단수·복수 어형을 구분하지 않는다).
4. **Given** 계정 언어가 영어인 사용자, **When** 같은 화면을 열면, **Then** 기존 영어
   문구가 변함없이 보인다.
5. **Given** 계정 언어가 한국어인 사용자, **When** 제품 이름(Mattermost, Agents)이 들어간
   문구를 보면, **Then** 제품 이름은 원문 그대로이고 나머지 문장만 한국어다.

---

### User Story 2 - 에이전트가 서버에서 보내는 안내 메시지도 한국어다 (Priority: P2)

에이전트가 대화 중에 서버 쪽에서 직접 게시하는 안내(원본 스레드 접근 불가, 회의
녹음 처리 중, 라이선스 안내, 검색 도구 사용 불가 등)를 한국어 사용자가 받으면 한국어로
읽는다.

**Why this priority**: 건수는 적지만(12개) 오류·제약 상황에서 나오는 문구라, 영어로
남으면 사용자가 상황을 이해하지 못한다. 화면 문구(P1)보다 노출 빈도가 낮아 P2다.

**Independent Test**: 한국어 로케일로 요청한 사용자에게 서버가 생성하는 안내 메시지
하나(예: 접근 불가 안내)를 받아 한국어인지 확인하면 된다. 웹 화면 작업과 무관하게
검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 계정 언어가 한국어인 사용자, **When** 더 이상 접근할 수 없는 스레드에 대해
   에이전트가 안내를 게시하면, **Then** 안내 문구가 한국어다.
2. **Given** 계정 언어가 스페인어인 사용자, **When** 같은 안내를 받으면, **Then** 기존
   스페인어 문구가 변함없이 나온다(기존 로케일에 회귀가 없다).
3. **Given** 계정 언어가 한국어이지만 번역이 없는 메시지 id가 있을 때, **When** 그
   안내가 나가면, **Then** 영어 원문이 그대로 나가고 오류나 빈 문자열이 되지 않는다.

---

### User Story 3 - 번역 파일이 깨지면 테스트가 먼저 잡는다 (Priority: P3)

이후에 영어 문구가 추가·삭제되거나 자리표시자가 바뀌었을 때, 한국어 번역이 뒤처지거나
문법이 깨진 상태로 배포되지 않도록 자동 검사가 막는다.

**Why this priority**: 이번 번역을 한 번 맞추는 것보다, 이후 upstream 선별 반영 때마다
영어 원문이 바뀌는 상황에서 품질을 유지하는 것이 장기적으로 더 중요하다. 다만 사용자에게
즉시 보이는 가치는 아니라 P3다.

**Independent Test**: 한국어 번역 파일에서 키 하나를 지우거나 자리표시자 이름을
바꿨을 때 테스트가 실패하는지 확인하면 된다.

**Acceptance Scenarios**:

1. **Given** 한국어 번역 파일에 영어 원문에는 없는 키가 있거나 영어 원문의 키가 빠져
   있을 때, **When** 테스트를 돌리면, **Then** 어느 키가 어긋났는지 이름을 들어 실패한다.
2. **Given** 어떤 한국어 번역의 자리표시자(예: `{agent}`) 집합이 영어 원문과 다를 때,
   **When** 테스트를 돌리면, **Then** 그 메시지 id를 들어 실패한다.
3. **Given** 어떤 한국어 번역이 메시지 문법(ICU)에 맞지 않을 때, **When** 테스트를
   돌리면, **Then** 그 메시지 id를 들어 실패한다.
4. **Given** 서버 번역 파일이 로더에 등록되지 않았을 때, **When** 서버 테스트를 돌리면,
   **Then** 한국어 로케일에서 영어가 돌아온다는 이유로 실패한다.

---

### Edge Cases

- 영어 원문이 복수형 분기(`one`/`other`)를 가질 때, 한국어 번역은 어떻게 쓰나?
  → 한국어는 복수 범주가 `other` 하나이므로 `other` 분기만 두고 개수는 자리표시자로
  넣는다. 영어 쪽 "`one` 분기 필수" 검사는 한국어에 적용하지 않는다.
- 영어 원문에 서식 태그(`<b>…</b>`)가 있을 때 한국어 번역이 태그를 빠뜨리면? → 자리표시자
  집합 검사가 태그 이름까지 포함해 잡는다.
- 사용자 로케일이 `ko-KR`처럼 지역 코드가 붙어 오면? → Mattermost는 언어 코드 `ko`로
  정규화해 넘긴다고 가정한다. 다른 형태가 오면 영어로 자연 폴백된다(기존 동작).
- 영어 원문에만 있고 아직 번역하지 않은 키가 생기면(upstream 반영 직후)? → 화면은 영어
  원문으로 폴백하고, 테스트(US3)가 빠진 키 이름을 들어 실패해 후속 작업을 강제한다.
- 번역 중 제품 이름·고유명사(Mattermost, Agents, MCP, LLM, OpenAI 등 서비스명)는?
  → 원문 유지. 리브랜드는 이 기능 범위 밖이다.
- 영어 원문이 같은 문장이지만 키가 다른 경우(같은 문구가 여러 화면에 쓰임)? → 각 키를
  모두 채운다. 키 집합 일치 검사가 누락을 잡는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 계정 언어가 한국어인 사용자에게 플러그인 웹 화면의 모든 사용자 표시 문구를
  한국어로 보여야 한다. 영어 원문 목록의 모든 키에 대응하는 한국어 번역이 있어야 한다.
- **FR-002**: 계정 언어가 한국어인 사용자에게 서버가 직접 생성해 게시하는 안내 메시지를
  한국어로 보내야 한다. 서버 영어 원문 목록의 모든 메시지 id에 대응하는 한국어 번역이
  있어야 한다.
- **FR-003**: 한국어 번역은 영어 원문과 같은 자리표시자(변수명·서식 태그) 집합을 가져야
  하며, 메시지 문법에 맞아야 한다.
- **FR-004**: 복수형 분기가 있는 문구는 한국어에서 단일 어형으로 자연스럽게 읽혀야 하며,
  개수 1과 여럿 모두 올바른 숫자가 표시되어야 한다.
- **FR-005**: 번역이 없는 문구는 영어 원문으로 표시되어야 하며, 빈 문자열·오류·식별자
  노출이 발생해서는 안 된다.
- **FR-006**: 기존 로케일(영어·스페인어)의 표시 결과는 이 변경으로 달라지지 않아야 한다.
- **FR-007**: 번역 용어는 기존 한국어 번역 초안(`temp/korean` 브랜치)과 Mattermost 한국어
  번역 관례를 따라 일관되어야 한다. 핵심 용어: 에이전트(agent), 도구(tool), 요약
  (summary/summarize), 스레드(thread), 채널(channel), 회의(meeting), 녹음(recording),
  전사(transcription), 승인(approve), 거부(reject), 시스템 콘솔(System Console), 라이선스
  (license), 플랜(plan).
- **FR-008**: 제품 이름·서비스명·고유명사(Mattermost, Agents, MCP, OpenAI, Anthropic, Azure,
  Bedrock 등)는 번역하지 않고 원문을 유지해야 한다.
- **FR-009**: 자동 테스트가 다음을 검사해야 한다 — (a) 한국어 번역 파일의 키 집합이 영어
  원문과 같다, (b) 모든 한국어 문구가 메시지 문법에 맞는다, (c) 각 문구의 자리표시자·태그
  집합이 영어 원문과 같다, (d) 서버 로더가 한국어 로케일에서 한국어 번역을 돌려준다.
  실패 시 어긋난 메시지 id를 이름으로 보고해야 한다.
- **FR-010**: 영어 원문 파일(webapp)은 소스에서 자동 추출되는 파일이므로 이 기능에서
  손으로 고치지 않아야 한다(constitution 원칙 V).

### Key Entities

- **번역 카탈로그(webapp)**: 메시지 키(내용 해시) → 한국어 문구. 영어 원문 카탈로그와
  키 집합이 1:1로 대응한다.
- **번역 카탈로그(server)**: 메시지 id(`agents.*`) → 한국어 문구. 영어 원문 목록과 id
  집합이 1:1로 대응한다.
- **용어집**: FR-007의 핵심 용어 대응표. 명세 산출물로 남겨 이후 번역 작업이 참조한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 한국어 로케일 사용자가 플러그인 주요 화면 5곳(오른쪽 패널 채팅, 에이전트
  선택기, 시스템 콘솔 Agents 설정, 채널·게시물 메뉴, 도구 승인 카드)을 열었을 때 영어로
  남은 사용자 표시 문구가 0개다(제품 이름·고유명사 제외).
- **SC-002**: 한국어 번역 카탈로그(webapp)의 키 수가 영어 원문 키 수와 같다(현재 1,029개).
  서버 카탈로그도 영어 원문 id 수와 같다(현재 12개).
- **SC-003**: 번역 카탈로그 검사 테스트가 (a) 키 하나 삭제, (b) 자리표시자 이름 변경,
  (c) 문법 오류 주입 각각에 대해 해당 메시지 id를 들어 실패한다(3/3).
- **SC-004**: 영어·스페인어 로케일의 기존 테스트 결과가 변경 전과 같다(회귀 0건).
- **SC-005**: 복수형 문구 전부(현재 15개)가 한국어에서 개수 1과 2 모두 올바른 숫자와
  자연스러운 문장으로 표시된다.

## Assumptions

- Mattermost 서버가 플러그인에 넘기는 사용자 로케일 값은 언어 코드 `ko`다. 지역 코드가
  붙은 형태는 영어로 폴백되며 이번 범위에서 다루지 않는다.
- 웹 화면은 사용자 로케일 이름으로 번역 파일을 찾는 기존 구조를 그대로 쓴다. 한국어
  번역 파일을 추가하는 것 외에 화면 쪽 로딩 방식은 바꾸지 않는다.
- 서버 쪽은 번역 파일을 명시적으로 등록하는 기존 구조를 유지하며, 한국어 파일 등록
  한 줄을 추가한다.
- 번역은 사람이 검수하기 전 1차본이다. 어색한 문구는 이후 PR로 고치되, 이번 기능의
  완료 기준은 "빠짐없이·문법에 맞게·용어가 일관되게"다.
- `temp/korean` 브랜치의 번역 초안은 참고용이며, 그 브랜치의 다른 코드 변경은 가져오지
  않는다.
- 스페인어 카탈로그가 영어 원문보다 적은 키를 가진 현재 상태는 이 기능의 범위 밖이다.
- 리브랜드(OKR.BEST 표시명 등)는 별도 기능으로 다룬다. 이 기능은 영어 원문의 의미를
  그대로 옮기는 번역만 한다.
