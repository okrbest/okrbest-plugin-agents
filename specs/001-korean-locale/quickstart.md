# Quickstart: 한국어 로케일 종단 검증

구현이 끝난 뒤 이 절차를 **실제 환경에서** 돌리고 절별 결과를 `tasks.md` 하단 표에 적는다.
환경이 없어 못 돌린 절은 `미실행`으로 적는다 — 통과로 적지 않는다.

## 준비물

- Mattermost 서버(Professional 이상이면 채널 기능까지 볼 수 있다)와 관리자 계정
- 플러그인 배포: 저장소 루트에서 `make deploy` (환경 변수 `MM_SERVICESETTINGS_SITEURL`,
  `MM_ADMIN_TOKEN` 또는 `MM_ADMIN_USERNAME`/`MM_ADMIN_PASSWORD`)
- 테스트 계정 2개: 언어 한국어 / 언어 영어

## A. 자동 검사 (게이트)

```bash
make apply                                 # 처음이면 manifest 생성
go test ./i18n/...                         # S1~S5
cd webapp && npm test -- src/i18n && cd .. # V1~V5 (en·ko 둘 다)
make check-i18n                            # en.json을 손대지 않았음을 증명
make check-style
```

기대: 전부 통과. `make check-i18n`은 `webapp/src/i18n/en.json`에 diff가 없어야 한다.

## B. 변조 실측 (SC-003) — 임시로 깨뜨려 테스트가 잡는지 본다

각각 변조 → `cd webapp && npm test -- src/i18n` → 되돌리기.

| # | 변조 | 기대 실패 |
|---|---|---|
| B1 | `ko.json`에서 키 하나 삭제 | "키 집합" 테스트가 빠진 키 이름을 출력하며 실패 |
| B2 | 어떤 값의 `{agent}`를 `{agents}`로 변경 | "자리표시자" 테스트가 그 키를 출력하며 실패 |
| B3 | 어떤 값에 닫히지 않은 `{` 삽입 | "ICU 파싱" 테스트가 그 키를 출력하며 실패 |
| B4 | `i18n/i18n.go`의 ko 로드 줄 주석 처리 → `go test ./i18n/...` | S2가 "영어가 돌아왔다"로 실패 |

되돌린 뒤 `git status --porcelain -- webapp/src/i18n i18n`이 비어 있어야 한다(ko.json 추가분 제외).

## C. 화면 확인 (SC-001) — 한국어 계정으로

계정 설정 → 표시 → 언어를 **한국어**로 바꾸고 새로고침한 뒤, 각 화면에서 영어로 남은
사용자 문구를 센다(제품명·서비스명 제외). 기대값은 전부 0.

| # | 화면 | 여는 법 | 결과 |
|---|---|---|---|
| C1 | 오른쪽 패널 채팅 | 채널 헤더의 Agents 아이콘 → 새 채팅. 입력창 안내·버튼·빈 상태 안내 | |
| C2 | 에이전트 선택기 | 오른쪽 패널 상단 에이전트 이름 클릭 | |
| C3 | 시스템 콘솔 Agents 설정 | 시스템 콘솔 → 플러그인 → Agents. 항목명·도움말·경고 | |
| C4 | 채널·게시물 메뉴 | 게시물 "..." 메뉴의 요약·액션 아이템 항목, 채널 헤더 메뉴 | |
| C5 | 도구 승인 카드 | 도구를 쓰는 에이전트에게 요청 → 승인 카드. 개수 1·여럿 모두 확인(SC-005) | |

## E. 회귀 (FR-006)

- 영어 계정으로 C1~C3을 다시 열어 기존 영어 문구가 바뀌지 않았는지 본다.
- `cd webapp && npm test`(전체)와 `make test` 실패 목록이 기준선과 같은지 diff.

## 기록

결과는 `tasks.md` 하단 "완료 검증" 표에 절 번호(A/B1~B4/C1~C5/D1~D2/E)별로 통과·실패·
`미실행`과 증거(명령 출력 요약, 스크린샷 파일명)를 적는다.
